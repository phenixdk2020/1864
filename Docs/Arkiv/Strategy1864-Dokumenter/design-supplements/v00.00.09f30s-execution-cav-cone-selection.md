# v00.00.09f30s — Execution State, Defensive CAV Reserve, Cone QA & Selection Persistence

## Purpose
F30S consolidates the QA fixes discovered after F30R: execution-state completion, defensive cavalry placement, range-cone readability, command selection persistence, LOS-gated anti-cavalry reaction, cavalry hover information, dismounted Dragon split/remount, and post-arrival movement stability.

## 1. Blue order state = physical execution
Blue no longer means the last standing intent. It means that some subordinate or HQ is still physically executing the order.

Execution contributors include:
- company mission movement not yet arrived;
- Major HQ still moving to HqGoal;
- Regiment HQ still relocating behind Majors;
- Brigade/Division follow still outside settle tolerance;
- cavalry move/reform/charge still active.

When all of these settle, the button returns red even if Defend/Hold remains the current intent.

### Defensive-stability hardening
`PrototypeDefensiveStability09F29Y` must not re-arm an already reached HqGoal. If the Major is within the settle tolerance of the stabilized defensive goal, HasHqGoal is cleared. This prevents false active execution and repeated stabilization log spam.

## 2. Defensive cavalry reserve geometry
During `FORSVAR HER`, each attached cavalry unit is anchored behind the battalion it supports rather than around the Division objective.

Current QA geometry:
- ~150 m rear of supported battalion anchor;
- ~45 m outward lateral offset.

Purpose: cavalry remains a genuine reserve/flank-security element and does not appear in front of the infantry defensive line.

## 3. Range-cone QA language
Dragon and infantry share one visual rule:
- active CLOSE/MED/LONG = strong/opaque/thicker;
- non-active physical ranges = faint reference;
- HOLD = all ranges reference-only.

Dragon fan geometry uses explicit mirrored side rays to avoid the one-sided kink observed in QA.

### Enemy TEST cones
Prussian infantry cones are visible in TEST/QA even without normal player selection. This is only for verifying facing, range and active fire-policy. It does not provide firing authority or target knowledge.

True gameplay later gates enemy cone visibility behind LOS/FOG.

## 4. LOS-gated anti-cavalry reaction
Enemy infantry may fire on cavalry only when all are true:
1. actual LOS exists;
2. cavalry is inside the selected fire-policy range;
3. cavalry is inside the infantry fire cone.

Automatic mounted-threat/Square reaction also requires LOS. A QA-visible cone does not create magical target awareness.

## 5. Selection persistence
Issuing a point/facing order to Division, Brigade, Regiment or Major must not clear the selected HQ.

The shared facing-order input suppresses legacy empty-ground selection clearing while an order is pending. The same HQ remains selected after commit so HUD and command circles remain available.

## 6. Cavalry mouse-over parity
`BattleManager` hover resolution now recognizes cavalry as well as infantry.

CAV hover shows:
- unit name/type;
- current/initial strength and losses;
- morale/cohesion;
- mounted/dismounted state;
- formation;
- AI/order phase;
- command parent;
- Dragon fire-policy/range/ammo while dismounted.

## 7. Dismounted Dragon split and remount
Dismounted Dragon is functionally split:
- ~75% mobile combat group;
- ~25% horse holders plus horse park anchored at the dismount point.

A normal dismounted move moves only the combat group. Horse holders and horses remain at the original dismount position.

`STIG OP` while away from the horses becomes a return-to-horses task:
1. HUD shows `TIL HESTE...`;
2. combat-group centre returns to the horse park;
3. remount begins automatically when the combat group is gathered;
4. world positions are preserved during root recentering to avoid a visual snap.

## 8. Finite AttackHere arrival
`ANGRIB HER` is a finite positioning mission at company level.

On arrival:
- movement ends;
- company holds the assigned attack slot;
- OfficerAI does not receive a fresh nearest-enemy chase mission;
- normal fire-policy/range/cone can still engage enemies;
- parent mission no longer rewrites facing every frame;
- FormationMotion owns the final visual turn.

Precise-arrival hardening also clears stale attack intent before re-enabling OfficerAI. This removes the observed loop:
`ARRIVED -> autonomous chase -> march column -> hardening pulls back -> line -> chase again`.
