# v00.00.09f30g — OOB input / visibility hotfix

## Problem
F30F screenshots exposed three regressions inherited from the F30D/F30E layering:
1. F29V's legacy OOB status renderer still drew black `190 KLAR` patches on top of the unified fixed-column OOB.
2. Cavalry OOB rows used `GUI.Button` and an explicit drag state machine on the same rect. `GUI.Button` consumed the mouse events first, so selection and drag/drop could fail.
3. Semantic zoom knew only infantry companies, Majors and Regimental HQ. Gardehusar/Dragon plus Brigade/Division HQ therefore lacked operational/strategic counters and higher HQ also sat too far behind the normal QA view.

## F30G fix
- Unified F30D+ OOB is the sole visual owner.
- Legacy F29V status, old infantry OOB, old cavalry OOB and F30B/F30C OOB renderers are disabled.
- Cavalry row is visual-only plus explicit event state machine:
  - click = select,
  - double click = focus,
  - hold+move = drag,
  - release on valid HQ = attachment reparent.
- Valid attachment targets remain Division, Brigade, Regiment, Major A / 1. Bataljon and Major B / 2. Bataljon.
- Semantic zoom adds I/CAV Gardehusar/Dragon counters and X/XX Brigade/Division HQ counters.
- Strategic renderer suppression now includes cavalry and higher HQ.
- QA spawn/follow distances are tightened while preserving command hierarchy and movement authority.

## Runtime authority
No new combat authority is introduced. F30G is UI/visibility/input/QA-placement hardening over F30E/F30F gameplay.
