# v00.00.09f30o — Higher AI arming, shared target circle & true F29G HUD parity

## Purpose
F30O fixes two runtime authority defects observed in the 2026-09-19 QA recording and closes the remaining HUD parity defect.

## 1. Higher AI ON is an armed state
Turning Division/Brigade AI ON must not issue any movement intent by itself.

During a higher-HQ cascade:
- Regiment enters AwaitHigherMission;
- Major/Battalion enters AwaitHigherMission;
- Company Officer AI is held;
- CAV enters VENTER PÅ HQ-ORDRE;
- stale Battalion missions are not executed;
- stale inherited CAV missions are discarded when higher AI is re-armed.

A fresh committed higher mission clears the waiting state and delegates execution downward.

## 2. Shared objective placement
Division/Brigade no longer use the separate legacy click handler for normal HUD orders. They use PrototypeOfficerFacingOrder09F29G, identical to Regiment/Major.

Pending position order behaviour:
- colored objective circle follows the valid ground cursor;
- Brigade QA radius: 64 m;
- Division QA radius: 84 m;
- click places the objective;
- drag supplies explicit facing;
- Escape or RMB cancels pending placement.

## 3. True runtime HUD parity
PrototypeUnifiedCommandHud09F29G is the authoritative renderer for Division, Brigade, Regiment, Battalion and Company command HUDs.

Higher HQ therefore shares the exact runtime geometry used by Regiment:
- same panel height;
- same header rectangle;
- same ENHEDSINFO / AI block;
- same command column dimensions;
- same two-row 3x2 officer order grid;
- same subordinate-status column;
- same active/inactive button styles.

The old HigherCommandHQ OnGUI remains fallback-only.

## 4. Black top edge
The shared HUD draws an explicit 2 px black top edge and disables inherited header border slicing, removing the green line seen above the Regiment HUD.
