# PROJECT 1864 — Designmanual v00.02.00 — Del 1

## 1. Executive summary

PROJECT 1864 er et historisk grand-strategy-spil, hvor kampagnen bevæger sig kontinuerligt i realtid med pause og hastighedstrin, mens større eller udvalgte sammenstød kan overtages som separate taktiske 3D-slag. Det strategiske lag skal have tempo og overblik i stil med Hearts of Iron IV, mens selve slagene skal have den operationelle tyngde, synlige formationer, ildafstande og kommandofriktion, man forbinder med Grand Tactician. Spillet skal dog have sin egen identitet: historisk OOB, forsinkede ordrer, autonome underordnede, reel logistisk geografi og en data-model hvor tab, ammunition, moral og officerer er de samme objekter på begge lag.

Den første fulde kampagne tager udgangspunkt i krisen og krigen 1864. Danmark, Preussen, Østrig og Sverige-Norge er kernemagter; efterfølgende kan systemet udvides til flere stormagter og andre konflikter 1848–1871. Arkitekturen må derfor ikke hardcode dansk organisation eller 1864-specifikke regler. Nationer skal kunne have forskellige organisationshierarkier, doktriner, våben, kommandokulturer og politiske muligheder.

| Designmål | Slutversion |
| --- | --- |
| Strategisk tid | Kontinuerlig simuleret tid med pause og flere hastigheder. Strategiske hære marcherer, reorganiserer, forsynes, observerer og kæmper samtidigt. |
| Taktiske slag | Real-time 3D-slag med infanteri, artilleri, kavaleri og ingeniører. Spilleren kan selv føre slaget, delegere eller auto-resolve. |
| Skala | Historiske mandskabstal simuleres; grafisk repræsentation er som standard ca. 1 model pr. 10 mand, dynamisk justerbar efter performance. |
| OOB | Nation-specifik, datadrevet kommandokæde fra hær/korps til division, brigade, regiment, bataljon og kompagni, hvor niveauer kan være valgfrie. |
| Officerer | Officerer har skills, traits, personlighed, initiativ, aggression, disciplin og stabsevne. De kan handle selvstændigt inden for commander intent. |
| Ordrer | Ordrer har afsender, modtager, tidspunkt, rute, kommunikationsform, delay, acknowledgement og mulighed for fortolkning eller selvstændig reaktion. |
| Persistens | Et regiment der mister 173 mand i et 3D-slag, mangler de samme 173 mand på strategikortet bagefter. |
| Historisk plausibilitet | Spillet starter historisk, men simulationen må kunne udvikle plausible alternative forløb. |

Slutversionen skal desuden simulere den stat og de militære institutioner, som skaber hærene: befolkning, landbrug, byer, råstoffer, industri, handel, statsbudget, forskning, officersuddannelse, rekruttering og fredstidstræning. Krigsførelsen skal derfor være konsekvensen af flere års udvikling og prioriteringer, ikke kun af troppeplacering på kortet.

Enheder er vedvarende institutioner med egen lineage, fane, kommandører, veteraner, battle honours, personlige dekorationer og en dynamisk kronik. En fuldt genopfyldt enhed efter katastrofale tab kan have samme headcount som før, men lavere erfaring, dårligere NCO-kvalitet, svagere cohesion og tabt institutionel kontinuitet.

## 2. Spillets slutvision

### 2.1 Den samlede spilleroplevelse

Spilleren skal opleve tre perspektiver uden at skifte til tre forskellige spil: statsmanden, den operative øverstkommanderende og den taktiske feltherre. De tre perspektiver bindes sammen af samme tid, geografi og militære data.

- På nationalt niveau afgør spilleren mobilisering, krigsmål, diplomati, budgetprioriteter, erstatningsmandskab, materiel og strategisk retning.
- På operationelt niveau organiserer spilleren hære, udpeger officerer, etablerer depoter, vælger marchakser, giver ordrer og forsøger at koncentrere styrker hurtigere end modstanderen.
- På taktisk niveau fører spilleren styrker på en rigtig 3D-slagmark, hvor formation, terræn, syn, skudafstand, ammunition, moral, officerer og kommandoforsinkelse bestemmer udfaldet.

> **IKKE TO SEPARATE SPIL:** Et taktisk slag må aldrig skabe en alternativ kopi af hæren. Slaget låner de aktuelle enheder fra kampagnen, ændrer deres data og returnerer dem til strategikortet. Det er et absolut arkitekturkrav.

### 2.2 Kampagnens rytme

| Fase | Spillerens typiske aktivitet |
| --- | --- |
| Før krigen | Diplomati, mobilisering, OOB, udpegning af officerer, befæstning, depot- og transportplaner. |
| Operationsplan | Objectives, commander intent, marchordrer, samlingsområder, reserver og forsyningslinjer. |
| Realtidskampagne | Tid kører; information ankommer gradvist; underordnede reagerer; spilleren griber ind ved behov. |
| Kontakt | Reconnaissance eller kampkontakt identificerer fjendtlig styrke. Spillet afgør om der opstår skirmish, engagement eller større slag. |
| 3D-slag | Fight, Delegate eller Auto-resolve. Ved Fight flyttes strategisk tid til slagets start og fremskrives med slagets faktiske varighed. |
| Efter slaget | Casualties, missing, prisoners, ammunition, fatigue, cohesion, officer losses, captured materiel og retreat routes opdateres. |
| Operational aftermath | Vinderen skal stadig kunne forfølge, forsynes og reorganisere. Et taktisk nederlag er ikke automatisk strategisk kollaps. |

## 3. Strategisk realtid og verdenssimulation

### 3.1 Tidssystem

Kampagnen kører med en deterministisk eller semi-deterministisk simulationsklokke. UI tilbyder Pause samt flere hastigheder. Under motoren behandles forskellige systemer med forskellige tick-intervaller: bevægelse og kontakt relativt ofte, logistik og økonomi mindre ofte, politik og diplomati på længere intervaller. Det reducerer CPU-belastning uden at gøre verden mindre levende.

| System | Anbefalet logisk cadence | Bemærkning |
| --- | --- | --- |
| Army movement / contact | 5–15 simulerede minutter | Skal føles kontinuerligt; interpolation kan gøre visningen glat. |
| Orders / couriers | 5–15 minutter | Kontroller levering, ændret HQ-position og acknowledgement. |
| Supply consumption | 1 time | Mad, ammunition, forage/foder og transportkapacitet. |
| Recovery / fatigue | 1 time | Afhænger af march, vejr, ly, supply og officerer. |
| Replacements / hospitals | 6–24 timer | Ikke nødvendigt hvert minut. |
| Economy / production | 1 dag | Nationalt og regionalt. |
| Politics / diplomacy | 1 dag + event triggers | Events kan afbryde normale intervaller. |
| Weather fronts | 1–3 timer | Vejr påvirker movement, LOS, våben og veje. |

### 3.2 Pause og interrupts

- Spilleren kan altid pause manuelt i singleplayer.
- Konfigurerbar auto-pause ved slag, vigtige telegrammer, diplomatiske ultimata, officerers død, nye krigserklæringer og store forsyningsproblemer.
- Informationshændelser skal have severity, så små rapporter ikke konstant stopper spillet.
- Ved manuelt spillet 3D-slag sættes den øvrige strategiske simulation på hold; når slaget slutter, flyttes kampagneklokken frem til slagets sluttidspunkt. Andre allerede planlagte hændelser i tidsrummet afvikles efter klare regler før strategikortet genoptages.

## 4. Strategisk kort og geografi

Kortet skal være et 3D-reliefkort over Danmark, hertugdømmerne, Nordtyskland, Sverige-Norge og relevante søområder. Det skal både være visuelt læsbart på nation-niveau og præcist nok til at gøre veje, jernbaner, færgesteder, broer, floder og befæstninger operationelt vigtige.

### 4.1 Geografiske lag

- Politisk lag: stater, hertugdømmer, besatte områder, administrative regioner og ejer/controlling power.
- Militært lag: marchområder, objectives, front/contact zones, depoter, forter, havne og garnisoner.
- Transportlag: vejklasser, jernbaner, broer, færger, havne, sejlbare farvande og chokepoints.
- Terrænlag: elevation, slope, skov, hede, mark, mose, bymæssig bebyggelse, vandløb og kyst.
- Forsyningslag: supply throughput, depot radius, jernbanekapacitet, transportvogne, forage potential og congestion.
- Efterretningslag: kendte enheder, senest observeret, estimeret styrke, rekognosceringskvalitet og misinformation.

### 4.2 Regioner og fri bevægelse

Der bør ikke være et kunstigt hex-grid synligt for spilleren. Strategisk bevægelse kan bruge navmesh/graph over terræn og infrastruktur, mens regioner fungerer som administrative, politiske og logistiske beholdere. En hær kan dermed befinde sig på en konkret vej mellem to byer i stedet for blot at teleportere fra provins A til provins B.

## 5. Nationer, politik og krigsmål

Den militære simulation er kernen, men 1864 giver kun mening hvis krigen har politiske mål. Danmark behøver ikke besætte Berlin for at vinde, og Preussen behøver ikke erobre hele Danmark. War score skal derfor baseres på konkrete krigsmål, militær position, internationale relationer, krigsstøtte og viljen til at fortsætte.

- Danmark: territorial integritet, forsvar af nøgleområder, international støtte, bevarelse af hæren og kontrol over øerne/stræderne.
- Preussen: politisk løsning på hertugdømmespørgsmålet, militær demonstrering, position i den tyske magtbalance og begrænset eskalation mod stormagter.
- Østrig: allianceforpligtelse, prestige og egne interesser i den tyske magtbalance.
- Sverige-Norge: opinion, skandinavisme, kongelig politik, regeringsforsigtighed, risiko for stormagtskonflikt og mulighed for intervention.

## 6. OOB – Order of Battle og militær organisation

OOB skal være et førsteklasses domæneobjekt og ikke blot UI-nesting. Kommandoforhold påvirker ordre-routing, stabsbelastning, morale influence, reinforcement coordination og hvor hurtigt underordnede får lov til at handle.

### 6.1 Historisk baseline for Danmark

Den danske kamporden fra april 1864 dokumenterer den normale ramme som fire divisioner, brigader med to regimenter, regimenter med to bataljoner og bataljoner med fire kompagnier. De faktiske kampordener afveg naturligt efter tab, detacheringer og særlige opgaver. Det betyder, at spillet skal modellere både enhedens organisatoriske template og dens aktuelle parent/attachment.

Hærens overkommando → Division → Brigade → Regiment → Bataljon → Kompagni

| Niveau | Strategisk rolle | Taktisk rolle | Spillerstyring |
| --- | --- | --- | --- |
| Hær / øverstkommando | Teater, strategi, reserve, højeste HQ | Kan repræsenteres som HQ på slagmarken | Direkte |
| Korps | Valgfrit pr. nation; operationel gruppering | HQ / gruppe af divisioner | Direkte hvis nationen bruger niveauet |
| Division | Primær operationel formation | Stor taktisk formation | Direkte |
| Brigade | Mission, sektor, reserve, koordination | Vigtigste commander-intent niveau | Direkte / delegerbar |
| Regiment | Styrke, våben, historik, replacements | Primær synlig kampenhed | Direkte eller via brigade |
| Bataljon | Mandskab og fysisk formation | Primær manøvreenhed på terrænet | Direkte ved høj detaljegrad |
| Kompagni | Tab, officerer, ammunition og intern styrke | Underopdeling / visuel sektor | Normalt AI-styret |
| Individuel mand | Simuleret via enhedsdata | Visuel repræsentation, ikke selvstændig strategisk agent | Ikke direkte |

> **DATAMODEL:** Et niveau må ikke være obligatorisk. Danmark skal kunne have Army → Division → Brigade → Regiment → Bataljon, mens Preussen kan have Army → Corps → Division → Brigade → Regiment → Battalion. Engine-koden traverserer en generisk CommandNode-struktur.

### 6.2 Attachments og midlertidig organisering

- Artilleribatterier kan være direkte under division, brigade, korps eller reserveartilleri.
- Kavaleri, pionerer, train og andre støtteenheder kan tilknyttes midlertidigt uden at deres historiske parent slettes.
- Reorganisering tager tid og har command/staff cost; den er ikke øjeblikkelig drag-and-drop.
- Enheder kan detachere bataljoner eller kompagnier til garnison, skærmtjeneste, brovagt eller reconnaissance.
- OOB-versioner gemmes historisk, så efterrapporter kan vise hvem der faktisk var underlagt hvem på et givent tidspunkt.
